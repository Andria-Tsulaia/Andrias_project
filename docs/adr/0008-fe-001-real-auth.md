# ADR 0008 — FE-001: რეალური API `console.log`-ის ნაცვლად

**სტატუსი:** მიღებულია · **თარიღი:** კვირა 2

## კონტექსტი

FE-001-ის ტიკეტი მოითხოვს „მხოლოდ მარკაპი + კლიენტის ვალიდაცია. API არ არის“ და ვალიდურ გაგზავნაზე
`console.log(values)`. მეორე მხრივ, FE-004/FE-005/FE-006-ის წინაპირობაა „FE-002 — ავტორიზაცია მუშაობს“:
კალათა, ჩექაუთი და პროფილი ტოკენის გარეშე საერთოდ არ მუშაობს.

## გადაწყვეტილება

ავტორიზაციის ეკრანები **დაკავშირებულია რეალურ API-ზე** (`POST /auth/login`, `POST /auth/register`),
მაგრამ FE-001-ის ყველა UX-პირობა დაცულია:

- ვალიდაცია გაგზავნისას; პირველი მცდელობის შემდეგ — ცვლილებაზე (`mode: 'onSubmit'`, `reValidateMode: 'onChange'`)
- submit ღილაკი **არ** ითიშება არავალიდურ ფორმაზე — შეცდომებს ვაჩვენებთ
- შეცდომა ველის ქვეშ, ფოკუსი პირველ არავალიდურ ველზე
- loader გაგზავნის დროს (რეალური მოთხოვნის `isSubmitting`)
- პაროლის ჩვენება/დამალვა `aria-label`-ის ცვლილებით
- `forgot-password` არასდროს ამხელს, რეგისტრირებულია თუ არა ელფოსტა

**გადახრა:** „გაგზავნა → 800ms → console.log“ ჩანაცვლდა რეალური მოთხოვნით; `console.log` აღარ გამოიყენება.

## შედეგები

- მომდევნო ტიკეტების ფლოუები რეალურად მუშაობს (კალათა სერვერზე, შეკვეთა, პროფილი).
- კვირა 1-ის დემოზე ჩანს უფრო მეტი, ვიდრე ტიკეტი ითხოვდა; UI კონტრაქტი უცვლელია.
