# ADR 0007 — ავტორიზაციის ტოკენის შენახვა

**სტატუსი:** მიღებულია (კომპრომისი) · **თარიღი:** კვირა 2

## კონტექსტი

API აბრუნებს `accessToken`-ს. აპლიკაცია ბრაუზერის SPA-ია და ბექენდი (cookie-ს დასაყენებლად) არ გვაქვს.

## გადაწყვეტილება

ტოკენი ინახება `localStorage`-ში (`cyber.accessToken`), ერთ ადგილას — `src/providers/auth/token-storage.ts`.
წაკითხვა API კლიენტს გადაეცემა `configureApiAuth()`-ით, ასე `src/api/client.ts` არ იცის, სად ინახება ტოკენი.

## შედეგები

- **დადებითი:** F5-ზე სესია ინახება; კოდი მარტივია; არ საჭიროებს დამატებით ინფრასტრუქტურას.
- **უარყოფითი:** `localStorage` ხელმისაწვდომია ნებისმიერი JS-ისთვის → XSS-ის შემთხვევაში ტოკენი მოპარვადია.
  `HttpOnly` cookie უფრო უსაფრთხოა, მაგრამ ამ API-ს არ აქვს cookie-ს რეჟიმი.
- დაცვის ზომები: ჩვენ არ ვაწარმოებთ მომხმარებლის HTML-ს, არ ვიყენებთ `dangerouslySetInnerHTML`-ს,
  ბარათის მონაცემები `localStorage`-ში არასდროს ხვდება (იხ. FE-006), 401-ზე ტოკენი დაუყოვნებლივ იშლება.
