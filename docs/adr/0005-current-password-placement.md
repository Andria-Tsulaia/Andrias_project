# ADR 0005 — მიმდინარე პაროლი პროფილის ფორმაში, ცალკე მოდალის გარეშე

**სტატუსი:** მიღებულია · **თარიღი:** კვირა 4

## კონტექსტი

`PATCH /auth/me` ყოველ ცვლილებაზე ითხოვს `currentPassword`-ს (დაცვა ღია ლეპტოპთან მჯდომი სხვა
ადამიანისგან). ტიკეტი ორ ვარიანტს უშვებს: ველი ფორმაში ან დადასტურების მოდალი „შენახვაზე“.

## გადაწყვეტილება

პაროლის ველი **ფორმის ბოლოს, ცალკე „უსაფრთხოების“ სექციაშია**.

მიზეზი: სერვერის შეცდომა `400 INVALID_CURRENT_PASSWORD` ზუსტად ამ ველს ეკუთვნის და მომხმარებელს
პასუხის გასწვრივ ხედავს, სად შეასწოროს. მოდალში ეს ველი ფორმის კონტექსტს კარგავს, საჭიროებს
დამატებით მდგომარეობას და მეორე გაგზავნის ციკლს.

## შედეგები

- `400 INVALID_CURRENT_PASSWORD`-ზე **არ** ხდება გადამისამართება: API კლიენტი `401`-ს ამუშავებს
  ცენტრალურად (logout + `/login`), `400`-ს — არა. მომხმარებელი პროფილზე რჩება და ხედავს
  „პაროლი არასწორია“ შეტყობინებას ველის ქვეშ.
- „შენახვა“ გათიშულია, სანამ ფორმა „ბინძური“ არ არის (`isDirty === false`) — აქ ეს გამართლებულია,
  რადგან გასაგზავნი მართლა არ არის.
- წარმატების შემდეგ პაროლის სამივე ველი ცარიელდება.
