# ADR 0002 — კატალოგის ფილტრები URL-ში, არა `useState`-ში

**სტატუსი:** მიღებულია · **თარიღი:** კვირა 2

## კონტექსტი

ტიკეტი: „თუ ფილტრებს `useState`-ში შეინახავ და URL-ს არ შეეხები — დავალება მიღებული არ იქნება“.
საჭიროა ბმულის გაზიარება, F5-ის გადატანა და ბრაუზერის „უკან“ ღილაკი.

## გადაწყვეტილება

მთელი კატალოგის მდგომარეობა (`brand`, `cpu`, …, `minPrice`, `maxPrice`, `sort`, `q`, `page`)
ცხოვრობს **მხოლოდ** URL-ში, `useSearchParams`-ით. `useState` არ გამოიყენება.

- `readCatalogState(searchParams, defs)` — URL → მდგომარეობა
- `writeCatalogState(state)` — მდგომარეობა → URL (ნაგულისხმევი მნიშვნელობები URL-ში არ იწერება)
- `toApiQuery(state, defs)` — მდგომარეობა → API პარამეტრები (`price` → `minPrice`/`maxPrice`)

ერთადერთი გამონაკლისია ძებნის ველის ლოკალური მნიშვნელობა (debounce 400ms) და ფასის სლაიდერის
მნიშვნელობა დრაგის დროს — ისინი სინქრონდება URL-თან `useEffect`-ით.

## შედეგები

- ნებისმიერი ფილტრის/სორტის/ძებნის ცვლილება აბრუნებს `page=1`-ზე; გვერდის ცვლილება ინახავს დანარჩენს.
- მოძველებული `page`-ის შემთხვევაში (ბმული ძველია) აპლიკაცია ავტომატურად გადადის ბოლო ვალიდურ გვერდზე.
